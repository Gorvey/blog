这篇页面用于测试文档目录在多标题、多层级内容下的视觉表现。

## 模型选择基准

选择 AI Coding 产品时，可以先把模型能力、上下文窗口和工具调用稳定性拆开看。

### 上下文窗口

长上下文适合大型仓库阅读、跨文件重构和长文档问答。实际使用时，稳定的检索和压缩策略通常比标称窗口更重要。

### 推理与编码能力

编码任务里，推理能力决定复杂问题拆解，代码能力决定实现细节质量。两者都需要通过真实项目验证。

### 工具调用稳定性

如果产品支持终端、文件编辑或代码搜索，工具调用是否稳定会直接影响工作流连续性。

## 套餐评估

套餐价格不能只看月费，还要看额度、限流、可用模型和失败重试成本。

### 价格口径

同样是月费套餐，不同厂商可能按 token、请求次数、模型等级或并发能力计量。

### 额度与限流

额度足够但限流严格时，连续编码体验仍然会被打断。适合个人使用的套餐不一定适合团队协作。

### 模型组合

多模型聚合产品更灵活，但需要关注具体模型版本、切换成本和响应稳定性。

## 工作流适配

好用的 Coding Plan 应该嵌入日常开发，而不是成为单独打开的问答窗口。

### IDE 集成

IDE 插件需要具备清晰的上下文选择、可审查的 diff 和稳定的撤销路径。

### 团队协作

团队场景下，权限、审计、用量统计和统一配置会比单次回答质量更重要。

### 安全边界

涉及私有仓库时，需要确认数据保留策略、模型供应链和企业安全配置。

## 结论

这篇测试页覆盖了多个二级和三级标题，用来观察右侧 TOC 在不同屏幕和主题下是否稳定。
